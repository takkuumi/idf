# v3.3.0 F3 RS485-1 验收记录

## 根因证据

设备 F3、UART1（GPIO45 TX / GPIO46 RX）、9600 8N1、从站地址 1。FC03 地址 2300、数量 100 的请求为 8 字节，正常响应为 205 字节。

修复前 100 次连续读结果为 50/100 成功、50/100 超时；成功帧首字节约 53–60ms，完整帧约 231–233ms，CRC 与 TCP 基准全部一致。设备诊断显示 UART1 收到 102 帧、只发送 51 帧，最后一次 RX 长度 213 字节，符合本机 205 字节响应与下一请求粘连。串口尾部还捕获到反复的 `01 83 01 80 F0` 异常回流帧。

GPIO19 的 F3 接线表标识为 `485_AD0`，当前实现和旧固件都将其作为地址拨码输入；本次修复没有把它改作方向控制。

## 修复

`src/modbus/rtu_slave.rs` 增加有界请求帧提取；RS485 从站接收批次中只处理合法请求，忽略响应/异常回流。FC01–06 固定 8 字节，FC15/16 按 byte-count 计算长度，全部检查站号和 Modbus CRC。

## 实机放行要求

刷入 v3.3.0 后，在设备下载线拔除、RS485-1 总线独占、POLL 超时 1000ms 的条件下，连续 FC03 `2300/100` 至少 100 次，要求：完整帧成功率 100%、CRC 错误 0、数据与 TCP 基准一致、UART1 `tx_errors=0`。若仍出现异常，应优先检查 RS485 收发器方向/回显硬件和总线终端，不能把 GPIO19 当 DE/RE 使用。
