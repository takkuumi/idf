# Android 手持机网络配置验证计划

目标是验证手持机读取字段顺序、实际写入字段顺序、NVS 持久化和自动复位。

## 前置条件

- 固件已按 `docs/FLASH.md` 的完整命令烧录，保留 NVS；禁止只烧 ELF。
- 当前设备基线：IP `192.168.51.220`、掩码 `255.255.255.0`、网关
  `192.168.51.1`。
- 串口监控使用 115200 baud。

## 用例

1. 连接 Android 1.0.78，读取网络配置。界面必须显示基线 IP、掩码和网关。
   响应的线协议顺序是 IP、掩码、网关。
2. 只修改 IP 为 `192.168.51.125`，保持掩码 `255.255.255.0`、网关
   `192.168.51.1`。等待 BLE 断开和设备复位，串口应出现计划复位日志。
3. 设备启动后重新连接 BLE 并读取配置；三个字段必须与写入一致。
4. 断电重启后再次读取，确认 NVS 中的值保持一致。
5. 写入包含大于 255 octet 的无效 FC16 地址值，固件应拒绝请求且不复位。
6. 用 Modbus TCP 分别读取 2247–2258，确认地址顺序是 IP、掩码、网关；可写入
   一组测试配置并读取回环，确认 TCP 与 BLE 使用同一寄存器字段顺序。
