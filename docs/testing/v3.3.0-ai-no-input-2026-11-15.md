# v3.3.0 AI 无输入偏值排查与验收

日期：2026-11-15（Asia/Shanghai）。目标设备：F3 / ESP32-S3，IP `192.168.51.226`。

## 原因

AI 数据链路为 ADC 原始采样、8 点滑动平均、标定换算，再输出到 Modbus input register 和 Web。
无电流输入时，板上 ADC 仍有约 2948～2950 的原始读数。该值是 ADC/模拟前端的空载基线，不能直接解释为 mA。

旧固件 `MCA_F16V2_1_F48_BLE/nca9555.cpp::Get_Analog()` 在 MIN 或 MAX 任一为 0 时，都会把整组标定改用默认 `605/3016`。在反向 0..4095 映射下，空载 raw=2897 会产生约 203；raw=2944 会产生约 123。它还将映射结果小于 20 的值清零。因此客户看到的 200 多是默认标定把空载 ADC 基线显示成了有效归一化量，不是 200mA，也不是 Web 格式化错误。旧固件存在相同的默认回退行为。

先前 3.2.0 修复了单端标定被整组回退的问题，但当两个端点都没有有效值时仍可用默认参考换算。此次修复把这种情况明确作为“未标定”：不发布默认参考生成的工程量，保留原始 ADC 供诊断。已保存有效零点端点仍参与换算；原始 ADC、有效值与标定状态分别提供。

## 修复

- 无有效零点端点或端点非法时，AI scaled/input register 为 0，AI 状态为无效；Web 显示“未标定”及 `—`，并继续提供 `ai_raw`。
- 有有效零点端点时继续使用既有 MCA 兼容映射和 `<20` 死区，不自动学习或覆盖现场标定。
- Web `/getiodata` 增加 `ai_status` 和 `ai_effective.valid`，明确区分诊断 raw、有效标定与工程量。

## 边界

当前实机测试没有标准 4–20mA 源，不能据此宣称量程、线性度或 mA 精度通过。raw 空载基线来自真实 ADC 读数；本轮确认软件映射是“200 多”显示的直接原因，但没有电路注入/示波器测量来进一步定位模拟前端的电气偏置来源。已标定且输入开路时，如果现场要求严格诊断“断线”而非显示零，需另定义开路检测阈值及硬件输入行为，不能用本次显示修复替代该功能。
