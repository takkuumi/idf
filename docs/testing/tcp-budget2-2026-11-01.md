# Modbus TCP 请求预算与四端口公平调度验收（2026-11-01）

## 实施内容

- `MAX_REQUESTS_PER_TICK` 从 1 提高到 2。
- 每个 5ms 主循环 tick 先按监听端口轮转；每个端口最多启动一个业务请求。
- 其它端口没有就绪请求时，剩余额度才允许同端口的另一个客户端借用，避免连接空闲时浪费预算。
- 新业务请求增加 2.5ms 准入窗口；窗口到期后不再启动新业务，但仍刷新已有 TCP 响应并检查超时。
- 连接保留监听端口信息；端口重绑后按端口号重新映射，旧连接不会因端口数组重排而失去服务。
- 同端口连接按最近服务的连接 ID 轮转；连接关闭后以连接 ID 重新定位，不依赖已变化的 Vec 下标。
- 增加真实调度器 host 测试：端口轮转、同端口客户端轮转、时间预算、端口重绑、空连接、超时清理、发送刷新和 8 连接遍历。

## F3 实机专项

- 四个长连接并发运行 60 秒，每个端口使用独立 Q 点（Q1/Q2/Q3/Q4）执行 FC05，紧接 FC01 读取该 16 位线圈镜像；每端口 220 次写入，合计 880 次写/读循环，零错误。
- 502：写应答 P95 `15.59ms`，FC01 P95 `15.35ms`；P99 分别 `20.62ms`、`20.10ms`。
- 503：写应答 P95 `15.47ms`，FC01 P95 `16.01ms`；P99 分别 `17.33ms`、`16.88ms`。
- 504：写应答 P95 `12.96ms`，FC01 P95 `15.81ms`；P99 分别 `17.74ms`、`19.03ms`。
- 5002：写应答 P95 `15.94ms`，FC01 P95 `16.60ms`；P99 分别 `20.06ms`、`20.57ms`。
- 所有端口最大单次写应答 `121.95ms`，最大单次 FC01 读取 `30.93ms`；极端值受主机、以太网、调度和其它系统任务影响，不能用 P95 代替最大值。
- 测试结束后四个 Q 点均恢复，FC01 独立读回 `0xFE07`；网络、恢复模式和 RS485 错误状态正常。
- UART 运行超过 300 秒：无 panic、WDT、stack canary 或新的 ERROR；reset_count 保持 145。运行期间最大主循环工作约 `35.066ms`，仍存在 deadline miss，5ms 不是硬实时承诺。

另外完成 90 秒混合回归：四端口合计 `17,073/17,073` Modbus 请求成功，17 次 Web 健康检查成功，会话替换 0；该窗口包含较大的 FC03/FC04 读取，因此端口 P95 约 22～41ms。随后 120 秒 DO＋四端口读取复测完成 `780` 笔 DO 确认、后台读取 `16,802` 次，零错误，输出恢复成功；中间一次非独占窗口连接重置已保留为失败记录，不计入通过成绩。

## 与旧窗口的对照

此前 DO 混合压测在旧调度器下，四端口负载 FC05 P95 约 `35.87ms`、FC01 P95 约 `31.58ms`；本次负载模型只包含 FC05/FC01，不能视为严格同分布 A/B 试验，但结果显示写应答和线圈读取均已进入约 20ms 区间。旧窗口包含 Web/FC15/后台读混合流量，差异必须谨慎解释。

## 边界

- 20ms 目标针对 Modbus TCP 写应答和 FC01 读取，不是 PCA9555 物理寄存器确认，也不是继电器触点动作时间。
- 本轮未承诺 8h/72h 长测、F4 真机、真实负载接点、示波器脉宽或物理拔线故障注入。
- 端口预算与时间窗口仍需在真实 PLC 的报文长度、轮询周期和连接数量下复测；大 FC03/FC04 单请求不可被 2.5ms 窗口中断。
