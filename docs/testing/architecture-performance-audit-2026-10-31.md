# 性能与架构复核（2026-10-31）

## 已实施

- 事件总线分层：DI/AI/AO/DO 使用原子合并标志；IP 分配、Ethernet link、复位请求使用
  独立关键状态单槽。普通采样洪峰不会覆盖关键状态，也不会产生无意义的事件队列堆积。
- BLE DI 状态上报从 INFO 降为 DEBUG，避免现场输入抖动时每次变化都写串口。
- 修正文档与实现不一致的日志级别说明：当前生产默认 INFO，Modbus `0x0106` 当前未接入。

## 当前架构判断

### 主循环

5ms 主循环、非阻塞 TCP 状态机、10ms BLE 业务调度、20ms DI 去抖、100ms AI/AO 和
有界 DeviceActor 组合合理。没有证据支持直接缩短主循环或扩大任务栈；这类改动会增加
实时抖动或内部 SRAM 压力。

### 数据访问

配置和大块状态使用 RCU 快照，避免 Modbus 读取持有大锁；但当前 RCU 内部仍通过
`std::sync::Mutex` 保护 `Arc` 指针。高并发读取下这是潜在热点，必须先测量锁等待再考虑
原子指针/epoch 方案，当前未改。

### I2C

PCA9555/LED/NFC 的 bit-bang I2C 事务由物理总线锁保护。事务有界，当前能满足功能；
但锁覆盖完整 GPIO 时序，异常或竞争时可能消耗 CPU。建议后续增加事务耗时和争用计数，
再决定是否改成 I2C worker/可阻塞仲裁，当前未改。

### Modbus/RS485

RS485 从站独立任务、256B ADU 缓冲、单请求单响应，普通读取不触发 NVS。真正的吞吐边界
来自波特率、报文长度和 RTU 3.5 字符间隔；`uart_wait_tx_done` 的 20ms 是超时保护余量，
不是固定每帧延迟。当前未缩短，以免 DE/RE 尚未释放时误报发送失败。

### 内存/分配

协议响应和热路径使用 heapless/固定缓冲；组态解析、启动加载和 NVS 保存允许低频分配。
没有发现应立即迁移到 PSRAM 或扩大栈的热点。后续应以最小 internal heap、栈水位和分配
失败计数为依据。

## 后续建议（按优先级）

1. 增加 RCU 锁等待、I2C 事务、事件覆盖、BLE/TCP 队列丢弃、RS485 响应延迟和主循环
   p95/p99 遥测；没有这些数据不做无证据的微优化。
2. 对 RCU 读路径做高并发现场基准，再评估无锁快照替换。
3. 对 bit-bang I2C 做竞争和异常从设备测试，再评估 worker 化。
4. 对真实 PLC 做 RS485 高频读取、错 CRC、慢响应和连续帧测试；通过后再评估动态
   `uart_wait_tx_done` 保护余量。
5. 若需要更小的生产镜像，可另做 production log ceiling（INFO）构建；不要在现场
   通过未接入的 `0x0106` 寄存器调节日志。
