# 性能与架构复核（2026-10-31）

## 已实施

- 事件总线分层：DI/AI/AO/DO 使用原子合并标志；IP 分配、Ethernet link、复位请求使用
  独立关键状态单槽。普通采样洪峰不会覆盖关键状态，也不会产生无意义的事件队列堆积。
- BLE DI 状态上报从 INFO 降为 DEBUG，避免现场输入抖动时每次变化都写串口。
- F3/F4 PCA9555 bit-bang I2C 改为独立 `pca9555-i2c` worker；主循环读取 DI、提交 DO 和更新状态灯只访问原子缓存，硬件事务在 6KB 专用任务中完成并有 WDT/心跳保护。
- RS485 `uart_wait_tx_done` 保护余量改为按波特率的 2 字符时间（最低 3ms、最高 20ms），实际发送完成仍由 UART TX_DONE 提前唤醒。
- RCU 改为原子指针 + reader guard；写者交换快照后等待已开始读者退出再释放旧 `Arc`，读路径不再获取 `std::sync::Mutex`。
- 修正文档与实现不一致的日志级别说明：当前生产默认 INFO，Modbus `0x0106` 当前未接入。

## 当前架构判断

### 主循环

5ms 主循环、非阻塞 TCP 状态机、10ms BLE 业务调度、20ms DI 去抖、100ms AI/AO 和
有界 DeviceActor 组合合理。没有证据支持直接缩短主循环或扩大任务栈；这类改动会增加
实时抖动或内部 SRAM 压力。

### 数据访问

配置和大块状态使用原子 RCU 快照，Modbus 读取不再获取 `std::sync::Mutex`；写者只在读者退出后回收旧快照。适用边界仍是读多写少、读闭包短；写者会在读者长期占用时让出调度器。

### I2C

PCA9555/LED 的 bit-bang I2C 已由独立 worker 承担；主循环只读写原子缓存，NFC 仍通过物理总线锁与 worker 协作。worker 有独立栈、WDT/心跳和失败节流；真实 I2C 异常和 F4 多芯片高负载仍需现场验证。

### Modbus/RS485

RS485 从站独立任务、256B ADU 缓冲、单请求单响应，普通读取不触发 NVS。真正的吞吐边界
来自波特率、报文长度和 RTU 3.5 字符间隔；`uart_wait_tx_done` 余量已改为动态字符时间，不是固定每帧延迟。仍需真实 PLC 做高频、错 CRC 和慢响应测试。

### 内存/分配

协议响应和热路径使用 heapless/固定缓冲；组态解析、启动加载和 NVS 保存允许低频分配。
没有发现应立即迁移到 PSRAM 或扩大栈的热点。后续应以最小 internal heap、栈水位和分配
失败计数为依据。

## 后续建议（按优先级）

1. 增加 RCU 锁等待、I2C 事务、事件覆盖、BLE/TCP 队列丢弃、RS485 响应延迟和主循环
   p95/p99 遥测；没有这些数据不做无证据的微优化。
2. 对 RCU 读路径做高并发现场基准，关注写者在读者长期占用时的等待。
3. 对 bit-bang I2C worker 做竞争、异常从设备和 F4 多芯片测试。
4. 对真实 PLC 做 RS485 高频读取、错 CRC、慢响应和连续帧测试，确认动态余量不会误报。
5. 若需要更小的生产镜像，可另做 production log ceiling（INFO）构建；不要在现场
   通过未接入的 `0x0106` 寄存器调节日志。
