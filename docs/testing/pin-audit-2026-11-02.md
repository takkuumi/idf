## 结论

当前源代码中的有效引脚均在 ESP32-S3 GPIO 范围内，ADC 和 W5500 映射与芯片/参考工程一致。F4 不启用 LEDC，GPIO15～18 作为 ADC2 AI4～AI7；这是资源保护，不是功能遗漏。

| 功能 | 当前映射 | 静态结论 |
|---|---|---|
| W5500 SPI3_HOST | MOSI=12，MISO=11，SCLK=10，CS=9，INT=13，RST=14 | 与 `utilities.h` 一致 |
| UART0 | TX=43，RX=44 | 芯片默认下载/日志脚 |
| RS485-0 / UART1 | TX=45，RX=46，RTS/DE=7 | GPIO 合法；45/46 是启动绑带，需板级偏置实测 |
| RS485-1 / UART2 | TX=42，RX=41，无 RTS/DE | 与参考固件 TX/RX 一致；GPIO8 保留 AI3 |
| Default/F3 AI | GPIO1/2/3/8 = ADC1_CH0/1/2/7 | 与官方 ADC 表一致 |
| F4 AI4～AI7 | GPIO15/16/17/18 = ADC2_CH4/5/6/7 | 与官方 ADC 表及旧固件一致 |
| Default/F3 AO | GPIO15/16/17/18 LEDC | 与 F4 条件隔离，无引脚冲突 |
| Default/F3/F4 软件 I2C | IO=35/36，LED=38/37，PCA9555 | 与旧固件一致；Quad PSRAM 下可用 |
| F3/F4 电源/检测 | 21/33 电源，34 INT/ESP_STOP，39/40 光纤输入，19/20/47/48 拨码 | 芯片 GPIO 合法，变体条件隔离 |

## 已明确修正

1. 用户手册中的 W5500 旧映射（11/13/12/10/14/15）改为当前实际映射。
2. 用户手册中的 AI 6 路、F4 AO 4 路改为 Default/F3=4 AI、F4=8 AI、F4=0 AO。
3. 更正旧调查中 Default 仍使用 MCP23017 的假设；当前 2.7.0 基线的 DEFAULT/F3/F4 均为 PCA9555，MCP23017 驱动已删除。
4. 删除保持寄存器 `0x0000..0x0003` 是 AO 的过期说明；该区实际是旧 `PCtrlBuf` 控制字。
5. 修正 GPIO26～32 为 Quad Flash/PSRAM 保留区的过期注释。
6. 修正生产代码中的 Clippy 生产二进制问题：ADC/GPIO 嵌套条件和 F4 LEDC 分支冗余返回。

## 不能仅靠芯片文档确认的项目

- GPIO7 是否实际连接到本板 RS485-0 收发器 DE/RE：芯片允许使用，但这是板级连线问题；旧固件只显式配置 TX/RX，没有提供该连接的代码证据。
- GPIO3、GPIO45、GPIO46 都涉及启动绑带。它们运行时可作 AI/UART，但必须在上电采样窗口用示波器或串口启动日志确认外部收发器/4–20mA 电路不会改变绑带电平。
- GPIO33～37 在 Quad Flash/PSRAM 型号可作为普通 GPIO；若换成 Octal Flash/PSRAM，必须重新审查，不能沿用当前映射。
- 软件 I2C 使用推挽 SDA 是旧固件兼容行为，不等同于标准开漏 I2C。必须实测上拉、电平争用、NACK 和长线波形。
