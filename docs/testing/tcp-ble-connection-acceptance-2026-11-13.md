# TCP 连接复用与 BLE 广播健康验收（2026-11-13）

## 范围

本轮设备当时运行的功能源码与 2.8.0 版本号更新前完全相同；版本号只在本轮后续更新。板型为 F3，地址 `192.168.51.226`。串口 monitor 观察期间设备持续运行，未见本轮测试触发复位或 listener 故障重绑。

## TCP 结果

- 单一 TCP socket 对 FC03 `0x010E` 连续发送 20 个 transaction ID，端口 502 收到 20/20 个匹配响应；中位响应耗时 10.22 ms，最大 28.54 ms。
- 四端口各使用一个长连接连续读取 20 次：502 为 20/20（p50 10.21 ms，max 84.53 ms）；503 为 20/20（p50 10.10 ms，max 24.63 ms）；504 为 20/20（p50 10.01 ms，max 110.45 ms）；5002 为 20/20（p50 10.14 ms，max 17.91 ms）。
- 打开 8 个不发送 Modbus 帧的连接并等待 11 秒后，新连接成功完成有效 FC03（约 93.55 ms）。随后 502/503/504/5002 的新请求均成功，HTTP :80 返回 301 响应。
- 设备日志观察到一次 `max connections reached; rejected=1 active=8 (no reclaimable sessions)`。随后在保持 8 个未验证连接超过 10 秒后，新连接请求成功。这说明槽位满时可能短暂拒绝第 9 个连接；绝对期限到期后可以回收未验证会话，不能描述成满槽时完全无拒绝。
- 起初对未映射地址 `0` 的读取收到 `0x8103` Modbus 异常响应。该响应证明 TCP/Modbus 帧正常往返，属于寄存器地址不适用；改用已验证地址 `0x010E` 后按正常响应统计。

## 边界

TCP 客户端槽位仍为四端口全局共享 8 个。八个已验证的长期 PLC 会话占满时，第九个客户端会被拒绝，这是有界资源策略；服务不抢占仍活跃的 PLC 长连接。端口 `SO_REUSEADDR` 解决监听端口重绑定问题，不等于客户端连接池或会话复用。客户端应持久复用单个 socket，断线后退避重连；服务器端负责断开会话回收、未验证连接绝对超时和公平服务。
