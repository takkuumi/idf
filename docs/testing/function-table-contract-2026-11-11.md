# App 组态写入与运行时解析契约复核

日期：2026-11-12 后续复核；版本号仍为 2.7.0，工作树未提交。

## 已复现的根因

App 原始工具在编辑完记录后仍优先取 `_editingRecords` 缓存，导致忽略输入框的新数据。该路径现已改为明确解析当前原始记录，使用本区保存操作和本区反馈，并在清空表时确认。非法输入保留在原字段，不会发送写命令；保存绑定设备会话。

同时发现固件 D0/D1 使用同一种错误编码互相回读，掩盖了与业务运行解析器的格式冲突。使用修复前 HEAD 的实际保存/回读函数和当前未修改的 `parse_poll_table` 执行主机诊断，得到：

```text
D0_store_ack=true; D1_echo_match=true; runtime_result=Err("unordered logic offsets")
stored_first_pointer=2303; runtime_expected_offset=3; stored_record_word=0x0017; expected_index_attribute_word=0x0003
```

三个具体问题：保存了绝对地址而运行时读取相对寄存器偏移；把 D0 的传输长度字节混入业务记录；对记录的大端字段按小端拼寄存器。不能用“ACK 成功、D1 相等”证明业务能执行。

## 已做的源代码修复

`src/ble_at/logic_handlers.rs`：D0 仅按小端读取总数，去掉各条记录的传输长度，按大端业务字段保存；表头使用相对偏移和终止偏移，与当前 B1/B3/业务解析布局一致。D1 执行反向转换。补齐显式空表、数量/长度/尾随数据和用户结果区边界检查。

新验收门槛 `tests/host/run_function_table_contract.py` 执行实际生产保存、回读和 RS485 解析函数（仅 HAL/NVS 桩替代），包括真实 RS485 主站任务端口/站号/源地址/目标地址的结果断言。CI、发布检查和 `just test-function-contract` 已接入。

## 20+ 记录 B1/B3 多帧写入接入（软件实现，实机未验收）

Flutter 已按旧手持机真实协议接入完整 0x01 表多帧写入：B1 写 2300+ 数量/相对偏移/终止偏移表，B3 将完整规范 holding 表以每块最多 100 words 分块写入；回读通过 2300+ FC03 分块完成，再由规范编解码器逐记录核对。小于等于 244 字节仍走固件 D0/D1。

固件 B1/B3 接收改为连接会话代次绑定的 RAM 暂存。每个块长度/偏移/表头/终止地址校验；允许字节完全一致的重传；缺块时不提交，冲突覆盖、无 B1 的孤儿数据块、越界/跨连接数据拒绝，块可按任意顺序到达。只有所有声明 words 到齐且通过现有运行时 `parse_poll_table` 校验后，才一次发布完整 Holding 快照并同步写入 A/B 持久区。持久化失败时恢复先前活动表并保留后台重试；连接建立/断开会清理暂存，并通过活动表 CRC32 防止上传期间并发覆盖被静默冲掉。文本表先写并回读，再激活组态表；由于文本和 holding 是两个持久对象，突然断电恰好发生在两次写之间仍需真实掉电测试，尚不能称为跨对象原子事务。

验证：App 20 条真实模拟量记录的编码、B1/B3 Mock 端到端写入与 holding 回读测试通过；当前 Flutter 全量 211 项、静态分析通过。固件 Default/F3/F4 `cargo check`、F3 clippy `-D warnings`、F3 `cargo test --no-run` 均通过；host 生产核心 28 项及功能表真实代码契约 6 项通过。`--no-run` 只证明测试目标可编译，ESP-IDF target 单测未在本机执行。另已将 F3 2.7.0 以 no-skip 方式刷入，并通过真实 BLE 只读连接与组态读取；这不是 B1/B3 写入验收。

限制：尚未刷机，没有真实 BLE/NFC 传输、写 Flash 中断、掉电、重连/重试和重启后运行验收。旧手持机任意业务 transaction ID 得到支持，因为固件按寄存器区间和 B1 头表形态识别，而不硬编码动态事务号。"20+ 已实现"在此仅指软件路径与 Mock 验证，不代表生产硬件验收。

完整固件硬件回归、LoRa E22-400T22D V2 验收以及产物尺寸优化仍须按用户要求在 App 核对之后推进；本修复是 App 正确保存业务所依赖的接口修复，不代表整体硬件已验收。
