# v2.6.0 F3 Modbus TCP 只读压力测试（2026-11-03）

## 设备与范围

- 设备：ESP32-S3 F3，固件 `2.6.0`，编译标识 `9fd50da52c03-dirty`。
- IP：`192.168.51.226`；四个 Modbus TCP 监听端口：502、503、504、5002。
- 测试只读，不写 DO/Q 点、holding 配置或组态。
- 正式窗口：120 秒，四端口各一条持久连接，每 20ms 开始一轮，轮询 FC01、FC02、FC03（125 words 与 16 words）、FC04 状态/AI/版本，共 22,983 次成功请求。
- PC 侧校验每个响应的事务号、MBAP、单元号、功能码、字节数和响应长度。

## 设备侧观察

串口监控保持同一连接时，每 60 秒发布一次指标。有效压测附近 uptime=121 秒、184 秒的窗口记录：

- uptime 121s：`deadline_miss=3062`，主循环最大工作 `29135us`，p95/p99 桶 `7500us`。
- uptime 184s：`deadline_miss=4527`，主循环最大工作 `35900us`，p95/p99 桶 `7500us`。
- 压力结束后的 uptime 245s 窗口：`deadline_miss=1121`；uptime 305s、365s 窗口均回落至 `1`。
- 该计数是每个 60 秒窗口内 `main_loop` 单次工作超过 5ms 的次数，并非 Modbus 错误或复位计数。窗口边界并非与测试完全对齐，但升高与压力时间重叠，结束后回落。
- heap 约 2043–2045KB；内部 heap 最低约 52KB；RCU 最大回收等待约 10us。

结论：四端口协议请求在本轮负载下没有错误，设备没有复位或内存耗尽；但高负载明显挤压 5ms 实时主循环，观察到数千次超期。因此本测试不能支持“高负载下实时任务无影响”的结论。请求 P95/P99 约 22–25ms，单次最大约 51–53ms。需结合生产 PLC 实际轮询频率、请求类型和其他 IO 负载评估，暂不建议将满速 FC01/02 + 大 FC03/04 请求作为无限制持续业务。

## 不计入成绩的失败尝试

第一轮 8 连接无节流试验中，脚本遇到网络错误后未退避，在 120 秒内制造约 147 万次连接尝试且全部失败；其后设备 IP 暂时不可达并发生一次额外复位。该轮是无效压力试验，未用于延迟和吞吐统计。脚本已停止，设备重新启动并完成后续 120 秒受控压力测试。以后压测必须保留持久连接、限制速率并对连接失败退避。

随后尝试用 `serial_soak.py` 同步采集第二个 120 秒窗口也不计入成绩：采集器重连过程中触发了三次启动序列，网络窗口得到 14,078/14,246 成功和 168 个错误。该窗口与串口打开导致的复位相互干扰，不能用于判断固件在连续 Modbus 负载下的稳定性。生产测试应在串口已经稳定打开后再建立网络基线，测试期间不得反复打开串口。
