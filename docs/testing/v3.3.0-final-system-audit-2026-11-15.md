## F3 刷后真实设备检查

设备：ESP32-S3 F3，IP `192.168.51.226`，下载串口 `/dev/cu.usbserial-1430`，
外部 RS485 转换器 `/dev/cu.usbserial-14140`。刷写使用 DIO/40MHz/8MB，完整
重写 bootloader、分区表和 factory App，只清理 `otadata`，保留 NVS/holding。

- Modbus TCP 502 可连接，Web 登录页 HTTP 200。
- 型号寄存器 `0x08A5`：`0x00F3`，确认 F3。
- 版本通过 FC04 读取为 `330`，不是 FC03；FC03 访问该只读输入地址返回
  正确异常响应 `0x83/0x02`。
- RS485 错误寄存器 `0x0880..0x0885`：全为 0。
- 三路 RS485 配置保持 `[16384,1,0,1000,20]` 重复三组。
- Web IO 诊断：DI 有效、DI failures=0、DO readback 有效、DO queue depth=0、
  DO failures=0、LED errors=0。
- DO 读回状态为 `0xFFFF`，与空载测试板当前状态一致。
- AI 四路没有产生异常非零归一化值，当前读值为 0。

开始计时，不包含主机请求发送阶段；成功率及 CRC/数据校验结论不变。完整往返
口径和少量/批量读取基准见
[9600 分档吞吐实测](v3.3.0-rs485-read-size-throughput-2026-11-15.md)。

## TCP 长连接与公平性

502、503、504、5002 四个端口同时建立持久连接，每端口连续发送 50 个只读请求，
交替读取版本 `330` 和型号 `243`：总计 200/200 成功，无异常响应、断链或数据错误。
逐端口结果见 `tcp-four-port-audit.json`。

## BLE 射频检查

macOS CoreBluetooth 12 秒扫描发现两台广播名为 `Mesh`、且都带 IMC 服务 UUID
`4FAFC201-1FB5-459E-8FCC-C5C9C331914B` 的设备。为区分真实 F3，分别建立短暂
GATT 连接并只读执行 `GET_ETH_MAC (0xC6)`：其中一台返回
`58:e6:c5:42:a2:6b`，另一台返回 `fc:01:2c:05:64:8b`，与正在验收的 F3
设备身份一致。F3 的广播、GATT 连接、通知/写入传输及只读设备命令均通过；两台
设备在识别后立即断开，未写入任何配置或输出。

详细扫描和身份核对记录：
`log/hardware/rs485-f3-2026-11-15/f3-v330-postflash-system-audit/ble-scan.txt`。

这些是测试条件边界，不是本次发现的固件回归问题。
