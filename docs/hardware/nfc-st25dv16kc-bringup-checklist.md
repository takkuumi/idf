# ST25DV16KC 板级排查清单

2026-11-08 的旧 F3 板测试曾确认 ST25DV 未焊接，故当时无 ACK 仅代表旧板状态。用户已确认当前设备接入 NFC 模块；本次刷机后按“当前测试结果”记录探测结果。保持有限地址探测，避免盲扫共享 I²C 总线。

## 1. 断电检查

- 按当前板原理图确认 ST25DV16KC-IE6T3 的 VCC、GND、SDA、SCL、GPO、E0/地址配置网络。
- 确认 ST25DV 的 SDA/SCL 实际网络是否连接到 GPIO38/37 或 GPIO35/36。
- 确认没有把 ST25DV 的 SDA/SCL 接到 ESP32-S3 的 ADC、UART 或其它扩展板信号。
- 测量 SDA 对地、SCL 对地、VCC 对地的电阻，排查短路和焊桥。

## 2. 上电静态测量

设备启动后，使用示波器或万用表确认：

- ST25DV VCC 达到板级规定电压并保持稳定；
- GPIO21 和 GPIO33 的扩展板电源使能已经为高；
- SDA、SCL 释放时均为高电平；
- SDA/SCL 上拉连接到正确电源，且没有被其它器件强驱；
- NFC 天线和 GPO 不参与 I²C ACK 判断，不能用手机能否感应代替 I²C 测量。

旧板日志中两组候选线释放后均为 `SDA=1 SCL=1`。该结果不能推断当前板的芯片、供电或连线状态；当前板以本次刷机后的串口记录为准。

## 3. 总线波形

在一次启动探测期间观察：

- START：SDA 在 SCL 高电平期间下降；
- 地址字节：`0xAE`/`0xAF`（7 位 `0x57`）和 `0xAC`/`0xAD`（7 位 `0x56`）；
- 第九个时钟周期是否有目标 ACK；
- STOP 后 SDA/SCL 是否回到高电平。

不要向未确认的其它设备码发送寄存器地址或写入操作。

## 4. 通过后的软件验收

只有在任一系统地址出现 ACK 后，才继续：

1. 读取 `IC_REF=0x26`（K）或 `0x51`（KC），同时要求 `MEM_SIZE=0x01FF`、`BLK_SIZE=0x03`；按代际选择看门狗寄存器；
2. 读取并核对数据地址对应的 Mailbox 动态寄存器；
3. 用真实手机执行 ISO15693 FTM Mailbox 单帧请求；
4. 执行超过 242 字节的双向分片请求；
5. 验证 IP、RS485、组态和 holding 写入后的回读、落盘和重启；
6. 测试标签离场、重新靠近和会话代次失效。

## 2026-11-08 旧板证据

- 旧 F3 板诊断日志：`log/hardware/nfc/st25dv16kc-f3-line-level-2026-11-08.log`
- GPIO38/37 与 GPIO35/36：释放电平均为高，但系统地址无 ACK；
- PCA9555 worker 启动无 I²C NACK 告警，说明共享软件 I²C 基础路径没有出现明显总线卡死；这不能替代 ST25DV 供电和连线实测。

## 2026-11-11 当前板

用户已接入 NFC 模块。第一轮新固件读取 GPIO38/37 上的 `IC_REF=0x26`，因此后续按 ST25DVxxK 进行完整容量签名和 Mailbox 测试；GPIO35/36 无应答。不得再把旧板未焊接的结论套用到当前板。

当前实板的完整签名、安全会话和 Mailbox 初始化结果见 [2026-11-11 验收记录](../testing/nfc-hardware-verification-2026-11-11.md)。
