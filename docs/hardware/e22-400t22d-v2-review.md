## 已核对的接口形态

制造商资料的 D 型七针接口包含模式选择、UART、工作状态和电源引脚；不同封装的章节另列复位脚，不能跨封装照搬。

因此，F3 接线表的 `LORA_RST` 网络名不能直接证明该网络接到 E22 的独立 RESET；用户确认的 E22-400T22D D 型接口列出 M0/M1、UART、AUX、电源和地，没有独立 RESET 脚。固件仅保留旧版 GPIO21 启动拉高电平，不将它当作 LoRa 复位控制。必须查清 GPIO21 实际板级电路后，才能决定是否有其它控制功能或允许改变电平。

## 当前源码证据

- `src/config.rs::pins`：UART0 TX=GPIO43，RX=GPIO44。
- 普通固件 profile 默认关闭 UART0 RTU，避免和 UART0 控制台冲突；F3 的 LoRa release profile 使用 `lora` feature 和 `sdkconfig.lora.defaults`，关闭 console 后启用第三路 UART0 RTU。
- `LORA_M0_PIN=255`，没有驱动接线表所标的 GPIO26。
- 当前 GPIO21 保持旧固件已有的 HIGH 输出行为；实际含义和极性仍待板级核对。

## 固件硬件回归时优先解决

1. 核对模块七针与 F3 PCB 的真实连接，特别是 M0/M1、状态脚、GPIO21、GPIO26。资料标签与 Flash/PSRAM 保留资源有冲突时，不按标签直接配置 GPIO。
2. 核对 UART0 下载器、运行期控制台和模块的电气连接/隔离；禁止两条业务同时拥有同一 UART，也不以“插没插串口线”猜测模式。
3. 确认实物软/硬件版本后采用相应官方协议。先完成只读身份/参数确认，再实现受控配置、发送节流、忙碌处理、超时与恢复。
4. 核对供电、串口电平及工作模式时序；设置有界等待和错误反馈，不能因 LoRa 不在线拖住启动或其它硬件服务。
5. 完成有对端的双向通信、最大/分段帧、通信中断、断电启动及持续收发测试。只有 UART 初始化或模块应答，不等于无线业务验收通过。

按用户新增顺序，在 App 核对之后执行固件全硬件深度回归；完成正确性验证后，再做固件产物尺寸优化。

## F3 VBUS 路由更新（2026-11-12）

根据用户提供的 BCT4227 电路图，USB VBUS 参与 USB-UART / LoRa UART 硬件切换；不再以 GPIO 软件检测 USB 插入。F3 专用 `lora` build profile 已将 ESP-IDF 与 bootloader console 从 UART0 关闭，并允许统一 per-port RTU runtime 使用 UART0 第三逻辑端口。LoRa 模块处于透明传输模式时，业务承载为 Modbus RTU 帧；运行主/从模式遵循第三端口已保存配置，出厂默认为从站。对端串口未枚举期间不宣称 RF 收发成功；详细刷写与限制见 `log/hardware/lora-peer-2026-11-12/README.md`。
