# IMC v3.2.0 发布说明

## 本轮修复

- Web 所有 API 请求统一识别登录页重定向及 HTTP 401/403，停止后台轮询并转到登录页；OTA 的 XMLHttpRequest 采用同一判断。HTTP 500、网络断开不被当作会话失效。保留原服务端登录和路由协议。
- I 点有效反馈改成 18px 绿色实心圆点，其余状态指示点为 14px；表单网格间距 10px→16px，卡片间距 12px→16px，每个 RS485 端口使用独立卡片、卡内留白 18px、卡间距 16px。保持原页面结构和轻量内嵌实现，不增加前端运行依赖。
- 登录页增加默认隐藏的显示/隐藏密码按钮，带可访问名称和状态，不提交表单、不改变输入内容。
- AI 使用已保存的有效单端标定，仅为缺失端点补默认参考；拒绝反向、相等、超过 12-bit ADC 范围的标定组合。修正滑动平均启动期间漏计当前样本的除数。原 0..4095 输出单位、反向线性函数和小于 20 的死区保持不变。
- `/getiodata` 增加只读 `ai_raw`、`ai_effective` 诊断：原始平均 ADC、生效端点及 `full/zero/span/default` 来源。Web 明示归一化单位，避免把约 120 的 ADC 归一化值误当 120mA。没有新增 Modbus 地址或自动写零点。
- 合入前轮真实设备验收发现的组态末块栈溢出和 BLE 已 ACK 请求丢失修复：有界 staging 缓冲、RCU 快照回滚、原子待处理槽。不增加 SDK 主任务栈，不改全局事件队列实现。参见 [3.1.0 缺陷与实机证据](../testing/v3.1.0-real-device-acceptance-2026-11-14.md)。

## AI 空载 120 多的原因

在用户确认无电流输入的同一 F3 板上，修复前连续 60 组、240 个读数逐项核对：ADC 原始均值2943～2948，已保存的零点端点为 2941/2942/2942/2942，另一端均为 0。旧逻辑遇到任一端点为 0 就整对回退到 605/3016，导致保存的零点完全未参与换算。按实际 C/Rust 整数截断公式：

```
raw=2944: 4095 + trunc((2944 - 605) * -4095 / (3016 - 605)) = 123
raw=2945: 上式 = 121
raw=2946: 上式 = 119
```

240/240 与设备返回值精确一致。这是标定应用缺口导致的归一化零偏，不是 Web 随机显示，也不是 120mA 的实测电流。修复使用已存零点，不加大死区，不以任意开机输入自动归零。单端标定仍不等于完成标准电流源双点校准；实际电流精度和全量程线性须用标准源另验。

## 升级与验收

版本在 Cargo.toml、Cargo.lock、SDK app 描述统一为 3.2.0；生产包由干净 Git 提交执行 `scripts/release.sh all` 生成 DEFAULT/F3/F4。存储、GPIO、分区和对外寄存器布局不变，保留 2.7.0 以来的生产数据基线。常规升级禁止全擦 NVS/holding；Web OTA 只选择对应板型的 `*-app.bin`，初始化 `*-ota-data-initial.bin` 不能作为 OTA 固件。

测试过程、量化结果和缺少外设的验收边界见 [3.2.0 实机验收](../testing/v3.2.0-real-device-acceptance-2026-11-14.md)。旧 3.1.0 初版归档仍暂停交付，不覆盖旧标签或归档。
