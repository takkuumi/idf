# IMC v2.10.0 生产发布说明

v2.10.0 基于 v2.7.0 首个生产数据基线，版本包对应 `esp32s3-imc`，设备程序名为 `imc`。本版沿用 v2.7.0 的 NVS、组态和 holding 存储格式，属于兼容升级版本；没有新增从旧开发版本导入数据的兼容路径。

## 主要内容

- Modbus TCP 四端口共用有界的 8 个客户端槽位；支持同一 TCP 连接上的连续 Modbus 请求。
- 未完成首个完整 Modbus 请求的会话有 10 秒绝对期限；槽位满时仅回收已断开的会话或过期的未验证会话，不抢占已经验证的 PLC 长连接。
- 监听 accept 的瞬时资源错误不再触发四个端口整体重绑；端口调度公平轮转，单轮业务处理和新连接接纳均有界。
- BLE 广播增加静默故障续租机制；仅在未连接时检查和恢复广播状态。
- 软件复位增加统一外设收尾：主动关闭 BLE GATT/广播并熄灭 BT 灯，停止 W5500 驱动并关闭 PHY，RS485 DE 拉回接收态，PCA9555 DO/端口灯进入安全态，LEDC AO 输出清零。晚到的 BLE 回调不会在复位期间重新启动广播。
- 固件版本寄存器保留旧版三位编码；`2.10.0` 及多数字段版本使用扩展标记编码，新版 Flutter 已同步解析。
- `lora` 特性默认编译；仅 F3 板型启用 UART0 第三逻辑端口，F3 发布包使用关闭 UART0 控制台的专用 sdkconfig，避免日志污染 E22 透传数据。
- 包含本版已合入的设备配置、NFC、RS485、IO 和功能表契约修复。

## 存储与安装

- v2.10.0 沿用 v2.7.0 存储 schema，正常升级可保留 v2.7.0 的设备配置和组态数据。
- v2.7.0 之前的开发固件数据不属于支持的迁移来源；从旧开发固件首次切换时，按安装指南全擦并安装 v2.10.0。
- 选择与设备板型一致的 `default`、`f3` 或 `f4` 包。烧录必须使用包内的 bootloader、partition table、初始 OTA data 和 app，Flash 参数为 DIO / 40MHz / 8MB。

## 验证记录

- 本版主机回归：生产核心 28 项、NFC 17 项、BLE dispatch 5 项、功能表契约 6 项、控制逻辑解析 1 项、TCP scheduler 16 项、BLE 广播健康 22 项。
- 真实 F3 设备：四个 Modbus TCP 端口分别在单一 socket 上连续完成 20/20 个 FC03 请求；八个未验证空连接保持 11 秒后，新的有效 Modbus 请求成功，四个 Modbus 端口和 Web :80 随后均可访问。详细记录见 `docs/testing/tcp-ble-connection-acceptance-2026-11-13.md`.
- 设备运行期间观测到一次连接槽位满载拒绝，符合固定 8 会话上限；测试关闭空连接并等待回收后服务恢复。未验证此策略对 8 个长期活跃 PLC 客户端同时占满槽位时的第 9 个客户端提供接入保证。
- BLE 本轮通过状态机主机测试（含复位期间断线不重新广播）；真实射频扫描/断连恢复需结合设备附近环境做现场验收。
- 复位外设安全态的硬件最终确认需要串口连接的真实设备执行：观察 BT/以太网灯、RS485 DE 和 DO/AO 电平，并核对重启后 BLE/TCP 可重新上线。

生产发布必须由干净且可追溯的 Git commit 构建，并生成 `release/v2.10.0` 下三个板型的完整包及 SHA-256 清单。实际硬件批次仍应按对应板型执行上线验收。
