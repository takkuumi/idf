# IMC v3.1.0 生产发布说明

发布日期：2026-11-14。v3.1.0 延续 v2.7.0 生产存储基线和 v3.0.0 的设备协议，不改变 NVS 命名空间、持久化格式、分区表或外部寄存器地址。常规升级应保留 NVS、holding 和设备配置分区，仅更新应用镜像。

## 修复与架构调整

- **复位期间的持久化顺序**：配置、holding/组态、设备文本的 RAM 快照发布与对应 dirty 标记现在位于同一配置写屏障内。计划复位先取得同一屏障，再同步落盘；已经完成的写入不会因 dirty 标记稍后才设置而被漏存。落盘失败仍会取消计划复位并保留后台重试状态。
- **Web 附属配置**：系统信息更新纳入同一写屏障，复位前由现有 NVS 持久化流程完成提交。
- **RS485 从站收帧**：首字节等待独立于完整帧预算；收到首字节后按配置波特率使用 3.5 字符静默间隔逐字节收帧，避免 UART 驱动事件分段造成的短帧误判，并避免请求整块缓冲区时等到 250ms 才返回已有数据。
- **BLE 配置连接收尾**：保留已完整进入队列的协议帧，协议分发忙时延后处理；旧连接迟到事件不清理新会话。

这些调整没有要求重写 actor、RCU 或总线架构。当前使用的单一写者屏障覆盖共享配置快照与需要在计划复位前静止的用户可见状态；变更重点是将“RAM 发布 + dirty 通知”作为一个有序写事务。运行时读路径仍使用现有快照机制。

## 验证

- 主机回归：生产核心、BLE 分发、BLE 广播、TCP 调度、IO worker、RCU、NVS adapter 等通过；新增 `tests/host/check_reset_barrier.py` 固定检查配置/文本 dirty 标记及复位屏障的顺序。
- 固件验证：DEFAULT、F3、F4 release 构建通过，固定分区地址、manifest 和 SHA-256 校验通过；app 分别为 1,856,688 字节（78.7%）、1,848,112 字节（78.3%）、1,849,920 字节（78.4%）。`cargo test --locked --bin imc --no-run`、DEFAULT/F3/F4 clippy 和 F3+LoRa clippy 均通过且无 warning。
- RS485 硬件边界：只有接入真实从站并覆盖实际波特率、连续轮询、超时/CRC 和异常帧后，才能将 RS485 物理验收记为通过；软件构建和串口启动日志不替代该测试。

## 产物和升级

发布产物由 `scripts/release.sh all` 生成 DEFAULT、F3、F4 三种目录，包含 app、bootloader、分区表、初始化 OTA 数据、manifest 和 SHA-256 清单。现场升级不得刷初始化 OTA 数据或执行全片擦除；需要使用仓库的升级/刷机流程保留配置分区。
