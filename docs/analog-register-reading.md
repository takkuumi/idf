# 组态模拟量的数值地址与 Modbus 读取

依据当前 3.2.0 生产代码，而非只依据旧注释：`src/control_logic.rs::parse_channels / AnalogChannel::encode / analog_result_word`、`src/bus/backends.rs::read_input_reg_from_runtime / read_hold_reg_from_snapshots`。

## 常用 0～127 数值地址

采用 **FC04（Read Input Registers）** 读取。配置的“数值地址”是协议里的零基地址，不能直接加 30000/40000 当作报文地址。

同一数值的 FC03 在 0～127 读取控制字，FC04 读取监控/模拟量结果，两者不是同一个寄存器区。

- 配有有效工程量量程：结果通常是 IEEE754 float32，占目标地址 N 和 N+1 两个连续寄存器；高 16 位在前，寄存器内按 Modbus 大端，字节顺序 ABCD。必须一次读两个，避免把浮点高低字当作两个整数。
- 未配置有效工程量量程：原始归一化 U16，只占一个寄存器，值为 0..4095，不是 mA。
- N=100 的 POLL 示例：FC04、起始协议地址 100、数量 2，选择 ABCD float。若界面采用一基显示，则显示 101；传统输入寄存器引用为 30101。设备站号以端口配置为准。

## 边界与其它窗口

- 当前组态模拟量目标窗口：0..127、4000..4223（十进制）。两字浮点不能越过窗口末尾，因此起始地址至多 126 或 4222。避免占用其它组态/反馈结果地址。
- 4000..4223 用户镜像同时提供 FC03/FC04 读取；推荐统一按 FC04 读取监控结果。
- tauri 配置工具的 Channel 表单当前允许输入到 256；这不等于固件支持 128..256 作为组态模拟量结果目的地址。这一表单边界应另行与固件约束对齐，不能把越界配置后没有结果误解为换功能码即可读取。
- 物理 AI 归一化通道也可通过 FC04 直接读取 128 起的地址：F3 四路 128..131、F4 八路 128..135；每路 U16。这与组态按量程换算后发布到自定义“数值地址”的 float32 结果不同。
- 这些运行时采样/监控值不是每次写入 Flash；重启后由实际采样和组态重新发布。
